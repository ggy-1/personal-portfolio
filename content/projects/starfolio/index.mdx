## 背景与目标

需要一个能长期维护的对外窗口，同时承载四件事：我是谁、我会什么、我做过什么、我在想什么。简历 PDF 和 GitHub 主页各覆盖一部分，但无法统一叙事。

更重要的目标是：**这个网站本身就是作品**。它的性能、可访问性与代码结构会被面试官直接检验，所以「能跑」不是验收标准。

## 我的角色

独立完成全部工作：信息架构、设计 token、星空背景、内容管线与部署配置。

## 技术选型与理由

| 层面 | 选择 | 为什么不选另一条路 |
| --- | --- | --- |
| 框架 | Next.js App Router | Vite + SPA 的首屏白屏与 SEO 成本都要额外补，与目标冲突 |
| 内容 | 仓库内 MDX 文件 | CMS 会引入后台与鉴权，而作者只有一个人，Git 本身就是审核与回滚机制 |
| 数据 | 无数据库 | 内容更新频率是周级，构建期渲染后就是静态文件，运行时没有任何查询 |
| 样式 | Tailwind CSS 4 + CSS 变量 | 设计 token 需要同时被 CSS 与画布读取，CSS 变量是唯一能同时满足的选择 |
| 星空 | 原生 Canvas 2D | Three.js 约 600KB，只为一片星空引入 3D 引擎不划算 |
| 高亮 | 构建期完成 | 客户端高亮意味着每篇文章多 20–40KB JS，还会有「先明文后上色」的闪烁 |

## 核心难点与解决

### 一、星空不能抢首屏资源

星空是全屏 Canvas，如果和 Hero 标题抢主线程，LCP 会直接恶化。

解决办法是把「氛围」拆成两层：底色与星云用纯 CSS 的 `radial-gradient` 渲染，不依赖任何 JS；星点在空闲时初始化画布后接管。这样即使禁用 JS，首屏依然有氛围，也不会出现空白闪烁。

### 二、每帧只做一次 drawImage

最初的实现每帧清屏后重画全部 320 颗星点，中端安卓机上滚动明显掉帧。

改成：所有不闪烁的星点在初始化时一次性画进离屏画布，此后每帧只 `drawImage` 一次；只有数量封顶的约 30 颗闪烁星需要逐帧绘制，且用 `globalAlpha` 调制透明度而不是重建渐变。全程不用 `shadowBlur`——它是 canvas 上最贵的绘制路径。

### 三、掉帧自动降级

光靠优化参数不够，低端设备上仍然可能掉帧，所以加了单向降级链路：连续 60 帧平均耗时超过 24ms 就依次关闭闪烁、关闭视差，最后整体替换为静态星点，且不再尝试恢复。

暂停条件有三个：页面切到后台、画布离开视口、系统开启「减少动态效果」。

## 成果

- 首屏 JS 从 210KB 降到 84KB（gzip），主要来自把 `'use client'` 边界从页面顶层下沉到叶子节点；
- 六档宽度（320 / 375 / 768 / 1024 / 1440 / 1920）下均无横向滚动；
- 星空逻辑在低端安卓机上稳定 45 FPS 以上，切后台返回后正确恢复而不是重复创建画布。

## 如果重做一次

内容校验脚本会写得更早。第一版只校验了 frontmatter 的必填字段，结果出现过「技能引用的项目 slug 写错」和「文章封面路径不存在」这两类线上事故，都是靠人工发现的。现在这两项都会在构建期直接失败。
