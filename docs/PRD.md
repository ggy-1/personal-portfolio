## 1. 项目背景与目标

### 1.1 背景

需要一个能长期维护的个人对外窗口，用来承载四件事：**我是谁、我会什么、我做过什么、我在想什么**。现有的选择（简历 PDF、GitHub 主页、社交平台主页）各覆盖一部分，但无法统一叙事，也无法体现前端与设计能力本身——对于开发者来说，网站本身就是作品。

### 1.2 产品目标

| 优先级 | 目标 | 可衡量指标 |
| --- | --- | --- |
| P0 | 让访客在 15 秒内知道「你是谁、做什么、怎么联系」 | 首页首屏包含姓名/定位/CTA；跳出率目标 < 60% |
| P0 | 完整展示项目作品集，支撑求职/接单/申请 | 至少 6 个项目的结构化展示，含截图、技术栈、成果 |
| P1 | 通过博客沉淀技术内容，形成长期流量入口 | 累计 10+ 篇文章；单篇平均阅读时长 > 2 分钟 |
| P1 | 成为技术能力的可直接验证样本 | Lighthouse Performance / SEO / A11y ≥ 95 |
| P2 | 降低后续内容更新成本 | 新增一篇博客 = 新增一个 MDX 文件 + 一次 push，无需改代码 |

### 1.3 非目标（本期不做）

- 不做用户注册、登录、评论系统，不做服务端管理后台（没有服务端会话与真实鉴权）。
- 编辑入口 `/admin` 属于后续增量需求：它是纯客户端的本地模拟（数据存在浏览器），
  不引入后端与数据库，也不写前台内容。定位与边界见 §6 与仓库 `README.md` 的「后台管理」。
- 不做多语言（预留 i18n 结构，v2 再落地）。
- 不做在线支付、广告、数据统计后台。
- 不做 3D 场景/WebGL 大场景（星空以轻量方案实现，见 5.3）。

## 3. 信息架构与站点地图

```
/                     首页（Hero + 精选内容聚合）
├── /about            个人介绍（长文 + 时间线 + 简历下载）
├── /skills           技能展示（分类 + 熟练度 + 关联项目）

│   └── /blog/[slug]        博客详情
├── /contact          联系方式（或首页锚点区块，二选一）

├── /rss.xml          RSS 订阅
├── /sitemap.xml      站点地图
└── /robots.txt
```

**导航策略**：桌面端顶部固定导航（毛玻璃、滚动后透明度变化）；移动端底部 Tab Bar 或汉堡抽屉（见 5.7）。当前页高亮。首页各模块之间通过锚点导航（`#about`、`#skills`、`#projects`），但四大内容各自也有独立路由，保证可被搜索引擎和分享链接直接命中。

## 5. 设计要点

### 5.1 设计原则

1. **内容优先**：星空是氛围，不是主角。任何装饰不得降低文字对比度或阅读速度。
2. **克制**：一屏内只保留一个视觉焦点；动效服务于层级，不服务于炫技。
3. **一致**：颜色、圆角、间距、动效时长全部来自 token，不出现魔法数字。
4. **深色即默认**：设计从深色出发（而非浅色反相），保证深色下的层次与质感真正经过推敲。
5. **性能是设计的一部分**：动效与视觉效果必须给出降级方案。

### 5.2 色彩系统

采用三层 token：**primitive（原始值） → semantic（语义） → component（组件）**。

**Primitive**

| Token | 值 | 用途 |
| --- | --- | --- |
| `--c-space-900` | `#05070D` | 页面最底层背景（深空） |
| `--c-space-800` | `#0A0E17` | 区块背景 |
| `--c-surface-700` | `#111722` | 卡片背景 |
| `--c-surface-600` | `#182030` | 悬浮/选中卡片 |
| `--c-border-500` | `#232C3D` | 分隔线、卡片描边 |
| `--c-text-hi` | `#E9EDF5` | 主文本（对比度 ≥ 14:1） |
| `--c-text-mid` | `#A6AFC2` | 次级文本（对比度 ≥ 7:1） |
| `--c-text-lo` | `#6E7889` | 辅助/元信息（对比度 ≥ 4.5:1） |
| `--c-accent` | `#6EA8FE` | 主强调色（星蓝） |
| `--c-accent-2` | `#A78BFA` | 次强调色（星紫） |
| `--c-accent-soft` | `rgba(110,168,254,0.12)` | 强调色低透明底 |
| `--c-success` | `#4ADE80` | 状态 |
| `--c-warning` | `#FBBF24` | 状态 |
| `--c-danger` | `#F87171` | 状态 |

**Semantic**：`--bg-page`、`--bg-elevated`、`--fg-primary`、`--fg-secondary`、`--fg-muted`、`--border-default`、`--border-focus`、`--brand`、`--brand-gradient: linear-gradient(135deg, #6EA8FE, #A78BFA)`。

**规则**
- 强调色只用于：链接、当前导航项、主按钮、关键数据。单屏强调色出现次数 ≤ 5 处。
- 渐变仅用于大面积氛围（Hero、分隔光晕）与主按钮，不用于正文。
- 文字对比度：正文 ≥ 7:1，辅助信息 ≥ 4.5:1，任何状态下不低于 4.5:1。
- 主题切换：v1 默认深色；预留 `data-theme` 属性与浅色 token 槽位，浅色主题列 v2。

### 5.3 星空背景实现要点

**分层结构（由远及近）**

| 层 | 内容 | 表现 | 性能策略 |
| --- | --- | --- | --- |
| L1 底色 | 深空渐变 + 2–3 个模糊光斑（nebula） | 静态，CSS `radial-gradient` + 大 `blur` | 纯 CSS，零 JS |
| L2 远景星 | 密集小星点，1px，透明度 0.2–0.4 | 极慢闪烁（周期 4–8s） | Canvas |
| L3 中景星 | 数量较少，1–2px，透明度 0.5–0.8 | 闪烁 + 视差（≤ 6px） | Canvas |
| L4 近景星 | 少量 2–3px 亮星（带十字光晕） | 视差（≤ 12px）+ 闪烁 | Canvas |
| L5 流星 | 偶发 1 条斜向拖尾 | 每 8–20s 随机触发，时长 0.8–1.4s | Canvas |

**参数**

- 星点数量按宽度自适应：`< 768px` → 120，`768–1280px` → 220，`> 1280px` → 320。
- 视差跟随鼠标，采用插值缓动（lerp 0.05），避免生硬跟随；移动端不启用鼠标视差，改为滚动视差。
- Canvas 尺寸按 `devicePixelRatio` 渲染但上限 2，避免 4K + 3x 屏导致填充率爆炸。
- `requestAnimationFrame` 驱动；`document.visibilityState === 'hidden'` 时停止循环。
- 若 `navigator.hardwareConcurrency <= 2` 或检测到连续掉帧（连续 60 帧平均 > 24ms），自动降级为静态星点图（L1 + SVG/CSS 生成的固定星点）。

**降级与无障碍**

- `prefers-reduced-motion: reduce` → 关闭闪烁、视差、流星，仅保留静态星点。
- 星空层 `pointer-events: none`、`aria-hidden="true"`。
- 星空层 `position: fixed`，不参与文档流，不影响滚动性能。
- 正文容器使用 `background: rgba(5,7,13,0.72)` + `backdrop-filter: blur(8px)`（低端设备回退为不透明色），确保任何星点密度下文字都清晰。

| 用途 | 字体 | 字号（桌面 / 移动） | 行高 | 字重 |
| --- | --- | --- | --- | --- |
| 英文字体 | Inter / Geist | — | — | — |
| 中文字体 | 思源黑体 / HarmonyOS Sans / 系统默认 | — | — | — |

| 区块标题 H2 | — | 32 / 24px | 1.25 | 600 |

规则：正文单行宽度控制在 **60–75 字符**（`max-width: 68ch`）；中文段落 `letter-spacing: 0.01em`；标题与正文使用同一字族，通过字重与颜色建立层级，而非依赖多种字体。

### 5.5 布局与栅格

- 容器最大宽度 `1200px`，左右内边距：桌面 32px / 平板 24px / 移动 16px。
- 栅格：桌面 12 列（间距 24px），平板 8 列（20px），移动 4 列（16px）。
- 项目列表：桌面 3 列 → 平板 2 列 → 移动 1 列；博客列表：桌面 2 列 → 移动 1 列。
- 区块纵向间距：桌面 96–120px，移动 56–64px。
- 圆角：小 8px / 中 12px / 大 16px / 超大 24px / 胶囊 999px。卡片统一 16px。

### 5.6 动效规范

| 场景 | 时长 | 缓动 | 说明 |
| --- | --- | --- | --- |
| 悬停反馈 | 150ms | `ease-out` | 颜色/位移 ≤ 2px |
| 展开/折叠 | 250ms | `cubic-bezier(0.22, 1, 0.36, 1)` | 高度或透明度 |
| 页面区块入场 | 400ms | 同上 | 上移 16px + 渐显，`IntersectionObserver` 触发一次 |
| 路由切换 | ≤ 300ms | 同上 | 淡出 + 淡入，不做复杂转场 |
| 一致延迟 | — | — | 列表项入场 stagger 间隔 60ms，最多 6 项后不再叠加延迟 |

规则：**入场动画只播一次**（不使用反复刷新触发）；动画不得造成布局位移（CLS）；全部动画在 `prefers-reduced-motion` 下退化为即时显示。

### 5.7 响应式与多端适配

| 断点 | 目标设备 | 关键调整 |
| --- | --- | --- |
| `≤ 479px` | 小屏手机 | 单列、Hero 字号 32px、星点数 120、导航收起为底部 Tab |
| `480–767px` | 大屏手机 | 单列、卡片全宽、字号微调 |
| `768–1023px` | 平板竖屏 | 2 列、导航保持顶栏（含抽屉） |
| `1024–1279px` | 平板横屏/小笔记本 | 3 列、启用侧边 TOC |
| `1280–1919px` | 桌面 | 完整布局，容器 1200px 居中 |
| `≥ 1920px` | 大屏 | 容器仍 1200px，背景星空铺满，不做内容拉伸 |

适配要求：
- **无横向滚动**（任何宽度下 `scrollWidth <= clientWidth`）。
- 触摸目标 ≥ 44×44px，间距 ≥ 8px。
- 输入框 `font-size ≥ 16px`，避免 iOS 聚焦时自动缩放。
- 使用 `100dvh` 而非 `100vh`，规避移动浏览器地址栏高度问题。
- 安全区适配：`env(safe-area-inset-*)`（刘海屏底部 Tab Bar）。
- 移动端：导航改为底部固定 Tab Bar（4 项以内）或右侧抽屉；TOC 折叠为悬浮按钮。
- 支持 320px 宽度下的可用性（最低兼容线）。
- 打印样式：`@media print` 隐藏星空、导航、动效，正文转为白底黑字（简历页尤其需要）。

### 5.8 组件清单（设计系统最小集）

Button（primary / ghost / icon）、Tag、Card（project / post / skill）、NavBar、TabBar、Drawer、Timeline、TOC、CodeBlock、Lightbox、Toast、Skeleton、Divider、SectionHeader、Footer、EmptyState、SearchInput。

每个组件需定义：默认/悬停/聚焦/按下/禁用/加载 六种状态；聚焦状态必须有 2px 可见焦点环（`--border-focus`）。

### 5.9 可访问性（A11y）

- 语义化标签：`header / nav / main / section / article / footer`，标题层级不跳级。
- 所有图片有 `alt`；纯装饰元素 `aria-hidden`。
- 全站可键盘操作，焦点不可丢失；抽屉/弹窗需焦点锁定与 Esc 关闭。
- 颜色不作唯一信息载体（筛选选中态同时用颜色 + 描边 + 对勾）。
- 目标：Lighthouse Accessibility ≥ 95，axe 无严重级别问题。

## 8. 验收标准（关键场景）

1. 在 320px 宽度下打开任意页面，无横向滚动，文字可读，按钮可点击。
2. 打开首页，2 秒内看到姓名与定位；不滚动即可看到「查看项目」按钮。
3. 系统开启「减少动态效果」后，页面无任何自动动画，星空为静态。
4. 手机端滚动首页全过程，帧率稳定，无卡顿与抖动；切换后台标签页后动画停止。
5. 打开任一项目详情页，能看到我的角色、技术选型理由与至少一张项目截图。
6. 打开任一博客文章，右侧（桌面）目录随滚动高亮；点击代码块复制按钮得到可运行代码，不含行号。
7. 在移动端博客页可展开目录并跳转章节，跳转后目录收起。
8. 新增一个 `.mdx` 文件并 push，站点自动构建并出现在列表中，无需修改任何组件代码。
9. 将任一页面链接分享到社交平台，标题、描述、封面图正确。
10. 断开网络后刷新已访问过的页面，核心文字内容仍可显示（静态输出 + 缓存）。

## 9. 风险与开放问题

| 风险/问题 | 影响 | 应对 |
| --- | --- | --- |
| 星空动效在低端安卓机上掉帧 | 体验下降、耗电 | 星点自适应 + 掉帧检测自动降级为静态 |
| 技能熟练度主观、易被质疑 | 可信度 | 用「熟练/熟悉/了解」三档 + 关联实际项目佐证，不用百分比 |
| 项目内容长期不更新 | 站点显得荒废 | 项目加 `year` 与状态标记；页脚展示「最后更新时间」 |
| 博客写作成本高导致断更 | 目标未达成 | 首版预置 3 篇存量文章；后续以短笔记形式降低门槛 |
| 深色 + 大量动效可读性差 | 阅读体验 | 对比度硬性下限；正文区背景加半透明遮罩 |
| 是否需要浅色主题 | 部分访客偏好 | 预留 token 槽位，v1 不做，v2 视数据决定 |
| 是否需要联系表单 | 交互闭环 | 首版用 mailto + 复制，避免引入后端 |
| 是否需要中英双语 | 国际机会 | 内容目录预留 `i18n` 结构，v2 落地 |

**待确认（需本人决策）**

1. 导航采用顶部栏（桌面）+ 底部 Tab（移动），还是移动端也用抽屉？
2. 首页是「聚合型」（各模块摘要 + 锚点）还是「极简 Hero + 独立页面」？
3. 项目封面图与头像是否已有素材，还是需要生成占位图？
4. 是否需要访问统计，若需要接受第三方轻量分析工具吗？
